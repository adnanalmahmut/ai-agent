# Feature inventory

This inventory describes implemented product capability, not a roadmap.

| Area | Capability | Owner / evidence |
|---|---|---|
| Public web | Localized English/Arabic entry page, RTL/LTR, theme and language switching | `apps/web/src/app/[locale]/`, `apps/web/messages/` |
| Authentication | Email/password sign-up and sign-in, email verification, password reset, optional Google OAuth, sign-out | `apps/backend/src/core/auth/`, `apps/platform/src/features/auth/` |
| Sessions | Session listing/revocation and server-derived country/city metadata | `apps/backend/src/core/auth/`, `apps/backend/src/core/geoip/`, Platform user settings |
| User lifecycle | Reversible account deactivation/restoration; no public hard delete | `account-lifecycle.service.ts`, Platform administration |
| Platform administration | User listing, role changes, credential takeover boundary, deactivate/restore actions | `apps/platform/src/features/admin/`, auth lifecycle controllers/services |
| Organizations | Create/switch organizations, overview/settings, membership and invitation management, archive/restore, plus typed locale/timezone/currency defaults and a bounded business profile with optimistic replacement | `apps/backend/src/organization-settings/`, `apps/platform/src/features/organization/`, Better Auth organization integration |
| Product audit | Organization-owned append-only history for meaningful domain mutations, beginning with atomic business-profile before/after events and an owner/admin cursor-paginated read API | `apps/backend/src/organization-audit/`, `OrganizationAuditEvent` in `apps/backend/prisma/schema.prisma` |
| Authorization | Separate platform (`user`, `admin`, `super_admin`) and organization (`member`, `admin`, `owner`) domains | `apps/backend/src/core/auth/permissions.ts`, Platform permission gates |
| Mail | Log, SMTP, Resend, or SES transports with localized verification/reset/invitation content | `apps/backend/src/core/mail/`, `apps/backend/src/core/auth/auth-mail.ts` |
| Async work | PostgreSQL transactional outbox feeding BullMQ workers with lease/retry/idempotency contracts | `apps/backend/src/core/outbox/`, `apps/backend/src/core/queue/` |
| Agent foundation | Durable AgentRun acceptance and duplicate-safe background execution through a replaceable Mastra boundary, with runs pinned to exact code and immutable tenant-bound organization-agent versions, PostgreSQL configuration reload on every attempt, Zod-parsed configuration/input/output, an application-owned context assembler bounded by explicit chunk and character budgets, provider credentials resolved per run from the encrypted store, terminal transport failures reconciled to a durable outcome, and deterministic configuration failures recorded as final | `apps/backend/src/agents/`, `apps/backend/prisma/schema.prisma` |
| Organization agents | Authorized code-owned agent catalog plus one explicit installation per organization/agent, with definition-validated configuration, immutable enabled/configuration versions, transactional active-pointer switching, optimistic concurrency, paged history, and run acceptance/execution pinned to the selected immutable version; management is API-only in this train | `apps/backend/src/agents/organization-agent-installation*`, `apps/backend/prisma/schema.prisma` |
| Content ideas | `content-idea@1`, the first production agent: an organization-scoped asynchronous request grounded in the organization's own knowledge spaces, gated independently by `agents.enabled`, `content_ideas.enabled`, and an explicitly installed/enabled organization-agent version, bounded by `agents.max_concurrent_runs_per_organization`, with a required idempotency key bound to the request body and a polling status/result surface; missing/disabled installations remain bounded states and the frontend never auto-installs | `apps/backend/src/agents/definitions/`, `apps/backend/src/content-ideas/`, `apps/platform/src/features/organization/blocks/organization-content-ideas-block.tsx` |
| Control plane | Code-registered feature flags with organization-over-platform-over-default precedence, Zod-validated bounded runtime settings, and AES-256-GCM provider credentials that no read surface returns; all super-admin only and evaluated authoritatively in the backend, with a Platform operator surface for all three | `apps/backend/src/control-plane/`, `apps/platform/src/features/control-plane/` |
| Knowledge | Organization-owned spaces, documents, and embedded chunks in PostgreSQL with pgvector, retrieved by exact cosine search scoped to the organization and to the granted spaces inside the ranking query itself, bounded by an operator-owned chunk ceiling. Content-addressed ingestion revises a document only when its text changed, replaces its chunks in the transaction that writes it, and embeds them in the worker through the outbox. Authorization is a guard that runs before body validation and gates on `knowledge.enabled`; the Platform offers a per-organization management surface | `apps/backend/src/knowledge/`, `apps/backend/prisma/schema.prisma`, `apps/platform/src/features/organization/blocks/organization-knowledge-block.tsx` |
| Abuse control | Redis sliding-window limits for Nest routes and PostgreSQL-backed Better Auth limits | `apps/backend/src/core/rate-limit/`, auth configuration |
| Operability | Liveness/readiness, graceful shutdown, structured logging, request IDs, optional OpenAPI | `apps/backend/src/core/health/`, `lifecycle/`, `providers/`, `docs/` |
| Delivery | Immutable multi-image publishing, migration-gated automatic Staging CD, prepared exact-evidence Production promotion | `.github/workflows/`, `ops/lightsail/` |
| Recovery | Exact release manifests, application rollback, verified logical-backup and isolated restore-drill tooling | `ops/lightsail/ai-agent-deploy`, `ops/backup/` |

The public web application is currently a compact product surface. The Vite
Platform contains the operational product flows. Backend enforcement remains
authoritative when a client-side permission gate exists.
